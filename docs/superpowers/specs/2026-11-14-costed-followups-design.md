# MobileGH 最终审查后续项修复设计

## 目标与已批准范围

用户针对最终审查报告明确要求「有代价的都要修」。本设计覆盖报告中九项延后 Minor，以及组件异常、重复 Worker、前向兼容、设备流程、通用 GHES 主机和多设备渲染等可行动裁定。目标是消除实际缺陷，或把此前只能靠推断的行为变成有回归测试、可重复验证的行为，而不是删除报告中的问题描述。

九项 Minor 按原审查记录逐项对应为：①分享附件复制前缺少类型、数量与大小校验；②日志分享缺少三条英文文案；③Shortcut 组件标签硬编码英文；④组件/通知路径使用无人管理的 `MainScope()`；⑤导出的 `.log` 不清理；⑥`WidgetStore.savePullRequests` 为死代码；⑦GraphQL `force` 参数无效；⑧企业链接不识别裸 Host；⑨`FeatureFlowsTest` 覆盖被缩窄。第 1～4 节分别关闭前七项，第 5 节关闭第八项，第 8 节关闭第九项。

## 不变边界

- 保留所有现有未提交修改；不提交、不推送、不改版本、不发布。
- 不伪造私有 `linkIssueOrPullRequest` / `unlinkIssueOrPullRequest` API，不制作 Copilot 等假界面，不接官方 Firebase 推送，不增加语音、订阅或 Analytics。
- 不用 WebView 代替原生页面，不通过关闭安全检查来让链接或上传通过。
- 每项行为修改先写失败测试并观察 RED，再最小实现到 GREEN；最后运行全量单元测试、Release 构建和设备验证。

## 修复设计

### 1. 分享导入边界与清理

在复制系统分享附件之前验证 MIME、单文件大小、总大小和数量。保留现有单附件 10 MB 上限；新增每次最多 10 个附件、总大小最多 50 MB，均沿用现有附件上传能力。先验证所有已授权 URI 的元数据再开始复制；复制或持久化任一步失败都回滚本次已复制的文件和未完成元数据，并给出可理解提示，不影响之前的合法草稿。缓存文件必须位于应用专用目录，不能信任分享方给出的文件名或路径。

### 2. 文案与 Shortcut 组件

补齐日志分享缺失的英文文案；Shortcut 组件中的所有内置标签在渲染时通过现有国际化机制生成，持久化快照保存稳定标识/文案键而非某一语言的显示文本，语言切换不依赖碰巧刷新快照；自定义 Saved Search 名称保持用户原文。增加键值完整性测试，防止英文资源和默认文案漂移。

### 3. 组件协程生命周期与日志保留

把组件/通知路径里无人管理的 `MainScope()` 改为有明确所有者的作用域，或使用调用方/ Glance 提供的结构化协程；页面或 Provider 销毁时取消未完成任务，不能把进程级泄漏改名为另一个全局 Scope。日志导出每次写入后清理超过保留期及超出数量上限的旧 `.log`，只清理应用自己的导出目录，不碰正在分享的文件。保留策略采用实现者决定：保留最近 30 天且最多 20 个导出文件；先按天数再按数量清理，当前刚生成的文件无论数量如何都不删除，非 `.log` 文件和目录不处理。

### 4. 清理无效接口

删除无调用的 `WidgetStore.savePullRequests` 及只服务于它的测试代码。移除没有语义的 GraphQL `force` 参数，或让它真正绕过对应缓存；选择取决于实际调用链，不能保留一个让调用者误以为已强制刷新的参数。

### 5. 任意已配置 GHES 主机与裸 Host 输入

企业主机信任来源仍是当前账号的 API/Web Host，而不是 URL 自称企业站点。除 `*.ghe.com` 外，也允许与当前账号配置精确匹配的 HTTPS GHES 主机及其 Web/API 对应形式；其它主机仍交给浏览器。裸 Host 输入只有在补全为 HTTPS 后通过同一账号 Host 校验才路由。

Android 系统无法通过一个静态 manifest 自动接管用户任意填写的 GHES 域名；本实现覆盖应用内链接、复制/分享入口和明确发给应用的 VIEW Intent，不宣称未注册域名会自动弹出 MobileGH。

### 6. 组件内容归属与重复刷新

从保存的 dumpsys/logcat 和 Glance 会话实现确认空白 PR 组件、跨 Provider 内容错配与双 SessionWorker 的根因。修复必须同时保证：appWidgetId 与 Provider/数据类型一致；隐藏、删除、重建后不会复用旧类型快照；同一来源的重复刷新被合并，真实内容变化仍会更新。若设备日志不能证明某条路径，则用可复现测试或新增针对性诊断先定位，不能直接猜测补丁。

### 7. Schema 与公共 GitHub 路由回归

为未知枚举、额外字段、null/缺字段和公共 `api.github.com` 链接补充前向兼容测试。若测试暴露真实解析失败，再修复对应模型；核心详情在增强数据失败时仍须可用。

### 8. 流程验证与设备渲染

恢复 `FeatureFlowsTest` 被缩窄的有效覆盖，并为 Actions 重跑参数、Deployment Review 写入、分享失败续传、通知调度与账号隔离建立可重复的本地测试。使用当前连接的模拟器重新安装修复后的 Release 构建，验证日志分享、组件添加/隐藏/重建、分享与通知 UI；在两个可用显示配置或设备上检查明暗主题与布局。

真实账号上不存在待审批环境、没有网页会话、或没有物理设备时，不把本地测试写成“线上已验证”；这些外部条件会在最终报告中单独列出。

## 完成标准

- 九项 Minor 均有代码/测试关闭，不再以 deferred 形式出现。
- 组件和 Worker 的每个结论有证据；已证实根因必须修复，未能复现的项目必须有新的可重复回归覆盖和明确剩余外部条件。
- 全量单元测试与 Release 构建通过，设备验证结果按实际观察记录。
- 最终报告只陈述执行过的验证；未执行项不得以“应该可用”代替。
