# MobileGH 功能核对

本轮基于用户提供的 APK 清单/界面资源、分析文档和 GitHub 公开 schema 核对。APK 中存在某个组件，不代表第三方凭据具有相同服务端权限。该表描述实际实现与剩余差距，不宣称完整替代全部官方能力。

| 功能 | 当前实现 | 范围与限制 |
| --- | --- | --- |
| 登录 | 默认 GitHub 授权并自动注册数字审批设备，保留 Token 和 OAuth 设备码入口 | 系统浏览器完成登录；PKCE 和 state 校验回调，不保存网页密码或 Cookie |
| OAuth 续期 | 保存实际返回的刷新凭据，401 时按设备流程刷新并重试一次 | 不为没有刷新凭据的 PAT 或旧 OAuth 凭据伪造续期；未完成真实过期用户授权的端到端测试 |
| 验证器 | 登录前/设置均可打开、多账号、6 位码、倒计时、复制 | 用户需配置 GitHub TOTP 并主动导入密钥；不是官方数字批准 |
| 原生数字批准 | 自动设备注册、认证推送、默认监听、全局数字弹窗、系统通知、Keystore 签名并提交真实批准 | 使用具有 Mobile Auth 能力的原生 OAuth 上下文；首次打开申请通知和后台运行权限，设置可管理权限和监听。前台服务维持消息连接并补偿查询，强制停止或断网时需恢复后接收 |
| 组织与仓库 | 分页组织/成员身份/仓库所有者目录，按组织分组、筛选、刷新、指定组织诊断 | 当前凭据实际可见范围；权限、SSO 或请求失败会展示原因，不保证全部组织都可读 |
| 动态 | 首页/个人/组织的类型筛选，列表去重、稳定标识 | GitHub 事件 API 有范围和延迟限制；不承诺实时推送 |
| 搜索 / 链接跳转 | 搜索提交时识别仓库、Issue、PR、文件等 GitHub 地址并进入原生页面 | 支持无协议地址、HTTPS / SSH 克隆地址及 `owner/repo`；普通关键词和搜索语法保持原有搜索行为 |
| 剪贴板快捷打开 | 全局底部提示仓库名称，提供打开和关闭入口；识别分享文字中的链接 | 仅在应用处于前台并获得焦点时检查；同一剪贴板版本只提示一次，重新复制可再次提示；忽略个人主页、设置及标记为敏感的内容 |
| 系统分享与历史 | 接收 GitHub 文字链接，登录后继续打开；搜索历史、最近浏览与移除/清空 | 本机按账号保存 20 条搜索、50 个仓库，不上传历史 |
| 文件查找 | 当前分支的文件名/路径筛选，打开对应文件或目录 | 固定到索引提交，展示前 200 项匹配；递归文件树截断时提示结果不完整 |
| 代码搜索 | 全局及仓库内搜索、分页、匹配片段、原生文件跳转 | 默认分支索引；不完整或超过 1,000 项时提示缩小范围 |
| Blame | 作者、提交与源码，行号定位和提交跳转 | 公开 GraphQL；源码按同一提交读取，预览最多 5,000 行；源码不可用时保留归因并说明限制 |
| 草稿 | Issue/PR 评论、新建 Issue、Discussions 新建及回复自动保存与恢复 | Keystore 加密，账号与目标隔离；不会自动发表，成功提交才清理对应内容 |
| 仓库订阅 | 参与/@我、关注全部、忽略三种实际订阅状态 | 需要可调用公开订阅接口的 Token；不冒充仅发布等事件订阅 |
| 个人资料编辑 | 名称、简介、公司、地点、网站、Twitter、公开邮箱和工作机会 | PATCH /user 仅发送变化字段，需 Profile 写权限或合适的 OAuth/PAT 授权 |
| 成就 | 首页显眼入口、徽章预览、原生成就网格、等级及倍数 | 无公开成就 API；隐藏徽章不可读取，网页结构变化时可重试 |
| 自定义列表 | 首页列表预览和直达详情、原生 GitHub Lists 与本机分类；「已 Star」页可在全部 Star 与列表之间切换，列表明细分页读取；仓库页 Star 已 Star 时长按、或仓库菜单，打开与首页同源的列表多选，列表出现即可勾选，可同时加入多个列表或全部取消，已加入的列表排在最前 | GitHub 列表用公开 GraphQL；本机分类按账号保存并明确标注，列表成员变化与取消 Star 是不同操作；归属判断优先用 `Repository.lists` 一次请求读出，字段不可用时才退回扫描列表条目（有总量预算）；列表满 32 个不再支持新建，仓库所有者可把未 Star 的自有仓库加入列表 |
| Star 搜索与排序 | 「已 Star」页用官方同一条 GraphQL 查询在服务端搜索（`starredRepositories(query:)`，100 个/页），默认按 Star 时间倒序，也可改按更新时间或切正序；列表目录按名称或仓库数并切换正序 / 倒序；列表详情每页 30 个，正序用 `items(first:, after:)` 从头部往后读、倒序用 `items(last:, before:)` 从尾部往回读，条目只提供正序 / 倒序，搜索始终可用。首页收藏列表卡片区与 Star 列表页共用同一份搜索 / 排序状态。搜索按回车或按钮才生效，打字时列表不变 | 列表详情不做 Star 时间排序：列表条目不带进列表时间，`starredRepositories` 也不接受按仓库过滤，唯一可行办法是把 Star 全集扫一遍，Star 上万时完全跑不动，因此只保留正序 / 倒序；Star 时间排序只属于「已 Star」页的服务端星标连接（该连接 `orderBy` 的 ASC 与 DESC 都受支持）；倒序是服务端从列表尾部重新取数（`last` + `before`，翻页看 `hasPreviousPage` / `startCursor`），不是把已加载条目在客户端反转；未登录或服务端拒绝 `query` 时退回本地过滤并提示 |
| 贡献者 | 仓库底部前三位卡片、累计提交、周趋势、增删行、占比、时间范围、活跃周、逐笔提交 | 周统计不能冒充逐日精度；202/缺失/截断单独提示，未知指标显示 —；明细按 UTC 日期精确查询 |
| 版本比较 | 分支/标签/SHA 输入，分页提交、默认折叠代码 Diff | API 文件列表最多 300 个，达到上限提示；二进制或缺失 Patch 不伪造差异 |
| Discussions | 分类/回答筛选、加载内搜索、分页、正文、评论/回复、创建与回复 | 服务端限制仍生效；提交失败保留内容，不自动重复发布 |
| Issue / PR | Markdown、评论、表情、标签/指派/里程碑、审查、合并、折叠 Diff | 更高级的审查线程、Projects 关联与批量管理仍需完善 |
| 上传文件（夹） | 浏览代码页多选本机文件或文件夹；对象用 git 自己的传输（smart HTTP 的 packfile）推进仓库，再用 Data API 在基准树上生成新树、一个提交并快进分支，可选新分支与发起 PR | 单文件上限为 GitHub 的仓库硬限 100 MiB（实测 100 MiB 可推、101 MiB 被 GH001 拒）；三条 REST 写对象路径（`/git/blobs`、`/git/trees` 内联内容、`PUT /contents`）实测均在 40 MiB 拒收，因此不能用它们传大文件；超过 100 MiB 的文件自动走 Git LFS（basic 传输：`/info/lfs/objects/batch` 申请上传地址 → PUT 到存储 → verify；仓库里提交 `version/oid sha256/size` 指针文件，并把该路径的精确规则并进根目录 `.gitattributes`；GitHub 令牌只发给 github.com，不会发到存储服务器），LFS 自身上限按 2 GiB 拦截并标出原因；空仓库（无任何提交）也能直接上传：没有基准树可合并，改为本地构造 tree/commit 并与 blob 同一次 push 建出默认分支（此时不给选新分支或发 PR）；权限位由 shebang / 后缀或仓库同路径现有条目推断，SAF 不携带 POSIX 权限；树过大被截断时不做「无变化」判定，宁可重复上传对象；一个 pack 内不能放重复对象（服务端 index-pack 会整包失败），相同内容只推一份 |
| 下载 / 更新 | 应用内进度、资源详情、打开、历史/文件清理、按架构在线更新；仓库可按当前分支/标签下载源码 zip | 公开下载与图片按节点策略加速，私有资源带凭据直连；后台仍由 Android DownloadManager 传输；源码 zip 由 GitHub 实时打包，不含提交历史和子模块 |
| 诊断 | 分类日志、脱敏、清理、导出、崩溃记录 | 用户主动导出；未捕获异常记录不能替代真实设备复现 |
| 界面语言 | 设置 → 外观与语言：简体中文 / English / 跟随系统，默认简体中文，切换后立即生效 | 源码里的中文原文是词典的键（`tr` / `trf` / `trc`），英文译文在 `assets/i18n/en.tsv`，查不到退回中文；新增文案用 `tools/i18n_extract.py --check` 检查缺失译文；系统分享出去的内容、GitHub 返回的用户内容不翻译 |
| 设置布局 | 首页只有账号与七个分类入口，分类进入各自子页 | 分类：外观与语言、安全与隐私、两步验证与数字批准、网络与加速、Token 与 API 配额、存储与诊断、关于与更新 |
| 代码对比视图 | 提交详情、分支对比、PR 文件变更均可在「统一」与「分栏」之间切换，选择会保存 | 分栏为左旧右新，上下文行两侧相同、连续的删除与新增按顺序并排配对；每栏占半屏宽，长行在栏内换行；PR 的行内评论仍挂在对应行下方 |
| 图表读数 | 柱状图、折线图、每周贡献图点按、长按或拖动，在图上方弹出带日期的数值气泡 | 每周贡献图下方另有读数行与前后周按钮，不再展开长列表 |
| 私有徽章 | 仓库列表、置顶仓库、仓库页标题、项目、Gist 统一用灰色描边徽章，私有带锁 | 只标示 GitHub 返回的可见性，不推断 |

继续完善的公开能力包括 Projects v2 原生看板、更多审查线程、按事件的细粒度订阅、个人状态编辑和更多管理界面。Copilot、官方推送、Mobile 数字匹配审批、某些图片上传和第一方特权属于另一类服务端能力，必须分别核实支持路径。

证据：[认证报告](AUTH_CAPABILITIES.md)、[GitHub UserList](https://docs.github.com/en/graphql/reference/users#userlist)、[贡献统计](https://docs.github.com/en/rest/metrics/statistics)、[提交比较](https://docs.github.com/en/rest/commits/commits#compare-two-commits)、[Discussions](https://docs.github.com/en/graphql/guides/using-the-graphql-api-for-discussions)。
